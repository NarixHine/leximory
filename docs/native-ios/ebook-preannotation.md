# Ebook pre-annotation

The ebook-only More action opens one switch, on by default, while preserving an explicit opt-out. The sheet explains tapping underlined words; pricing remains in Account. Automatic failures, including quota exhaustion and exhausted retries, stay silent, and ready annotations remain readable.

The current page and its immediate neighbors prepare concurrently, with up to six active passage streams. EPUB extraction combines visible paragraphs into one page passage, splitting only above 1,600 UTF-16 units at grapheme boundaries. Its existing hidden pagination renderer supplies neighboring pages without moving the visible reader. PDFs use physical page text with the same size bound, scheduling the first passage of each page before later chunks. Leaving the reading window cancels obsolete work; turning the switch off or leaving the reader cancels every stream.

Web articles and ebooks share `server/ai/annotation-prompt.ts`, the language guides and compact `{{original||lemma||definition||etymology||cognates}}` output. Model configuration stays with each caller: ebooks use `mobileNanoAI` (DeepSeek), while web articles retain their existing settings. Ebook generation disables article trimming. Each complete annotation is parsed using the existing comment syntax and definition parser, resolved to an exact source occurrence, saved, and immediately emitted as NDJSON. The client explicitly forwards each model revision into the native readers so underlines update before the stream completes. Existing strokes keep their identity; new strokes fade in over 160 ms, with no entrance under Reduce Motion. Static ebook and article definition bubbles use the same native glass surface as the dynamic tray.

Batching by page avoids repeating the full language guide for each paragraph. The compact output avoids per-word JSON field overhead, and canceling consumption aborts AI generation. Completed passages replay without another model call. Durable quota receipts keep retries from charging twice. The prompt upgrade versions the result cache while preserving the previous quota-receipt identity, so refreshing an identical passage from the old prompt does not debit it again. Usage remains proportional to source characters at 0.25 commentary units per thousand characters.

The `ebook_preannotations` table was applied separately by the project owner. Its generated types are in `packages/supabase/src/types.ts`. The API keeps the source file immutable and stores private, versioned passage records. Vocabulary saves resolve the stored annotation rather than trusting a supplied definition or an expiring lookup receipt.

Rendering premise checked: absolutely positioned strokes inside the publisher document are not reliable in fragmented horizontal and vertical layouts. `EbookPreannotationTests.epubUnderlinesPreserveRubySourceAndPosition` measures actual painted pixels for both writing modes and short/nested versus long paragraphs. Strokes therefore belong in the outer reader viewport, with source range rectangles converted through the iframe. Source text, ruby and CFIs remain untouched.

Verification uses fake service transports and database HTTP responses through the installed SDK. Run the mobile checks and `EbookPreannotationTests`; no live account writes are required. Textless scans need an OCR extraction path before they can receive word annotations.
