# Ebook pre-annotation

The ebook-only More action opens one switch, on by default, while preserving an explicit opt-out. The sheet explains tapping underlined words; pricing remains in Account. Automatic failures, including quota exhaustion and exhausted retries, stay silent, and ready annotations remain readable.

New paid preparation starts only after the current page remains stable for three seconds. Neighbor extraction does not restart this dwell timer. Device-cached annotations appear immediately. The current page and its immediate neighbors then prepare concurrently, with up to six active passage streams. EPUB extraction combines visible paragraphs into one page passage, splitting only above 1,600 UTF-16 units at grapheme boundaries. Its existing hidden pagination renderer supplies neighboring pages without moving the visible reader. PDFs use physical page text with the same size bound, scheduling the first passage of each page before later chunks. Leaving the reading window cancels obsolete work; turning the switch off or leaving the reader cancels every stream.

Web articles and ebooks share `server/ai/annotation-prompt.ts` and the compact `{{original||lemma||definition||etymology||cognates}}` output. Model configuration stays with each caller: ebooks use `mobileNanoAI` (DeepSeek), while web articles retain their existing settings. Ebook generation reuses the existing word-definition field rules and curated contextual input/output references. It separates page selection/output instructions from single-selection lookup instructions. English keeps four references covering inflection, lexicalized adjective forms, whole phrases and omitted optional fields; French and Classical Chinese keep two, Japanese and other languages keep three. Full sample articles and unrelated article processing instructions are omitted. Web article and word-lookup prompts retain their existing behavior. DeepSeek uses low reasoning; its documented minimal setting maps to the same level. Each complete annotation is parsed using the existing comment syntax and definition parser, resolved to an exact source occurrence, saved, and immediately emitted as NDJSON. The client explicitly forwards each model revision into the native readers so underlines update before the stream completes. Existing strokes keep their identity; new neutral strokes appear at 35% of their final opacity and finish a 160 ms fade, with no entrance under Reduce Motion. Press feedback is immediate, and cached definitions open on release without waiting for double-tap recognition. Static ebook and article definition bubbles have a single native glass surface matching the dynamic tray; system presentation backing and custom content no longer stack materials.

Batching by page avoids repeating the language guide for each paragraph. The compact output avoids per-word JSON field overhead, and canceling consumption aborts AI generation. Completed passages replay without another model call. Durable quota receipts keep retries from charging twice. The prompt upgrade versions the result cache while preserving the previous quota-receipt identity, so refreshing an identical passage from the old prompt does not debit it again. Usage remains proportional to source characters at 0.25 commentary units per thousand characters.

The `ebook_preannotations` table was applied separately by the project owner. Its generated types are in `packages/supabase/src/types.ts`. The API keeps the source file immutable and stores private, versioned passage records. Vocabulary saves resolve the stored annotation rather than trusting a supplied definition or an expiring lookup receipt.

Temporary server-side JSON logs use event `ebook.annotation`, correlated by the database unit ID. They record the complete prompt, full generated output (including partial output on failure or cancellation), completion status, first-text/first-parsed-annotation timings, total duration and returned token usage. Logging failures do not fail generation.

Rendering premise checked: absolutely positioned strokes inside the publisher document are not reliable in fragmented horizontal and vertical layouts. `EbookPreannotationTests.epubUnderlinesPreserveRubySourceAndPosition` checks visible geometry, neutral color, immediate pointer feedback, single activation, source preservation and both writing modes with short/nested versus long paragraphs. Strokes therefore belong in the outer reader viewport, with source range rectangles converted through the iframe. Source text, ruby and CFIs remain untouched.

Verification uses fake service transports and database HTTP responses through the installed SDK. Run the mobile checks and `EbookPreannotationTests`; no live account writes are required. Textless scans need an OCR extraction path before they can receive word annotations.
